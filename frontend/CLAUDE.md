# seminai-fe-v3 — Frontend Rules

Stack: **React 19 + TypeScript + Vite + Tailwind v4 + shadcn/ui + TanStack Query + TanStack Router**

> Shared conventions (file size, no `any`, DRY, English) are in the root `CLAUDE.md`.

---

## Architecture: Atomic Design

```
src/components/
├── ui/          # shadcn/ui primitives — DO NOT EDIT manually
├── atoms/       # custom atoms (Logo, StatusBadge, FieldChip)
├── molecules/   # combinations of atoms (SearchBar, FormField)
├── organisms/   # complex sections (Sidebar, DataTable, JobForm)
└── templates/   # page layouts (DashboardLayout, AuthLayout)
```

### Rules

- **atoms**: single UI element, no business logic, only props.
- **molecules**: combine 2+ atoms, may have minimal local state.
- **organisms**: full UI sections, may use hooks and API data.
- **templates**: layout structure (header, sidebar, content area). No data fetching.
- **pages** (`src/routes/`): route-level components. Wire organisms into templates.

## Import conventions

- Use `@/` prefix for all imports: `import { Button } from '@/components/ui/button'`
- Prisma types: `import type { Job } from '@/types/prisma'`
- Generated API hooks: `import { useGetJobs } from '@/generated/api/jobs/jobs'`
- Never import directly from `@prisma/client` — use `@/types/prisma` re-exports.

---

## Data fetching

- All API calls go through **TanStack Query** (via Orval-generated hooks).
- Custom query wrappers go in `src/hooks/`.
- Default cache: `staleTime: 5min`, `retry: 1`.
- Auth: cookie-based (HttpOnly), managed entirely by the BE. No token logic in FE.
- User state: `GET /auth/me`.

## Analytics (PostHog)

- Fire events ONLY via `capture()` from `@/lib/analytics` (the only module importing `posthog-js`).
- Any new event must be added to the `AnalyticsEvent` union in `src/lib/analytics-events.ts` AND to `docs/analytics/TAXONOMY.md`.
- Send scalars/enums/ids/counts only — never message bodies or other PII. Outcome events (jobs/diagnosis/recommendations) are backend-owned; do not emit them from the FE.

## Naming conventions

| Case | Used for |
| --- | --- |
| PascalCase | components, types, interfaces |
| camelCase | variables, functions, hooks, props |
| kebab-case | file and directory names |

- One component per file.
- Hooks prefixed with `use`.
- Max 300 lines per file.

## Commands

```bash
npm run dev              # dev server (port 5173)
npm run build            # production build
npm run type-check       # TypeScript check
npm run lint             # ESLint
npm run prisma:generate  # copy BE schema + generate types
npm run api:generate     # export swagger + generate API hooks
npm run datasets:sync    # copy crop.json from seminai-be-v2 to public/datasets/
npm run datasets:build   # build cultivars-by-crop.json from EUPVP + date_raccolta
```

### Static datasets (production units wizard)

After changing files under `seminai-be-v2/dataset/crop_family/` or `public/datasets/varietà/`:

```bash
npm run datasets:sync && npm run datasets:build
```

- **Crops:** `public/datasets/crop.json` (source of truth in BE: `dataset/crop_family/crop.json`)
- **Cultivars + harvest hints:** `public/datasets/cultivars-by-crop.json` (built from EUPVP CSV + `date_raccolta.csv` + `crop-families.csv`)
- **BBCH PDFs** (`seminai-be-v2/dataset/dataset_crop_phases/`) are backend-only (agents / vector search), not used in the FE wizard.
