# seminai-fe-v3 — Frontend

You are an expert senior frontend engineer working on a React + TypeScript + Vite codebase using shadcn/ui and TanStack Query. Follow these rules strictly. If a request conflicts with them, propose the closest compliant alternative.

React 19, TypeScript, Vite, Tailwind v4, shadcn/ui, TanStack Query, TanStack Router, Orval (API codegen).

## Architecture: Atomic Design

```
src/components/
├── ui/          # shadcn/ui primitives — DO NOT EDIT manually
├── atoms/       # custom atoms (Logo, StatusBadge, FieldChip)
├── molecules/   # combinations of atoms (SearchBar, FormField)
├── organisms/   # complex sections (Sidebar, DataTable, JobForm)
└── templates/   # page layouts (DashboardLayout, AuthLayout)

src/routes/      # TanStack Router file-based routes (pages)
src/hooks/       # query/mutation hooks
src/services/    # api client, endpoints
src/types/       # DTOs, domain types
src/utils/       # shared utilities
```

### Layer boundaries

| Layer | Responsibility |
| --- | --- |
| **atoms** | Single UI element, no business logic, only props |
| **molecules** | Combine 2+ atoms, minimal local state |
| **organisms** | Full UI sections, may use hooks and API data |
| **templates** | Layout structure (header, sidebar, content). No data fetching |
| **pages** (`src/routes/`) | Route-level: params, query/mutation orchestration, page state |

**Rule:** server-data orchestration must live in **pages/templates** or **hooks**, not in atoms.

- All API calls go through **TanStack Query** (via Orval-generated hooks).
- Custom query wrappers go in `src/hooks/`.
- Default cache: `staleTime: 5min`, `retry: 1`.
- Auth: cookie-based (HttpOnly), managed entirely by the BE. No token logic in FE.

## React guidelines

### Component boundaries

- Prefer **presentational** components that receive props.
- Route/page components handle routing params, query/mutation orchestration, page-level state.
- Avoid prop-drilling by extracting organisms or using context **sparingly**.

### State management

- **Server state:** TanStack Query only (no duplicating into local state unless strictly necessary).
- **Local UI state:** `useState`.
- **Derived state:** compute from props/query results (avoid storing derived values in state).
- For heavy derived computations: `useMemo` (only if measurable).

### Performance

- Avoid premature memoization; use `React.memo`, `useCallback`, `useMemo` **only** when:
  - passing callbacks to memoized children
  - expensive calculations
  - preventing re-render storms in large lists/tables
- Consider virtualization for large lists.

## useEffect rules (STRICT)

Use `useEffect` only for **side effects**, not for derivations.

### Avoid useEffect for derivations

If you can compute a value from props/state/query data, compute it directly in render or via `useMemo`.

### Allowed use-cases

`useEffect` is ONLY for:

- subscriptions (websocket/event listeners)
- imperative DOM interactions (rare)
- syncing with external systems (localStorage, analytics) when unavoidable

### Correct dependencies & cleanup

- Always include correct dependencies.
- Always cleanup subscriptions in the return function.
- Prevent stale closures: put values in dependency array, or use refs for mutable values.

### Async in useEffect

Never call async directly in the effect callback. Use an inner async function:

```ts
useEffect(() => {
  let active = true;

  (async () => {
    const res = await doWork();
    if (!active) return;
    setState(res);
  })();

  return () => {
    active = false;
  };
}, [deps]);
```

### If effect reacts to query data

Ask: "Can I avoid this by using query `select`, derived values, or computed render logic?" Prefer avoiding effects.

## TanStack Query standards

### Query keys

Use stable, structured query keys:

- List: `['users', { page, pageSize, search }]`
- Detail: `['user', userId]`

Rules: keys must be **stable** and **serializable**. Avoid unstable objects/functions in keys.

### Typed hooks pattern

Create typed hooks in `src/hooks/` and keep api calls in `src/services/`:

- `useUsersQuery(params)`
- `useUserQuery(userId)`
- `useUpdateUserMutation()`

### Mutations + cache updates (IMPORTANT)

After any update/create/delete, cache must be correct **without requiring a full refresh**.

Use `useMutation` with:

- `onMutate` for optimistic updates (when it improves UX)
- `onError` rollback if optimistic
- `onSuccess` to update cache precisely
- `onSettled` to invalidate if necessary

#### Cache update rules (strict order)

When an entity is updated:

1. Update **detail** cache: `setQueryData(['entity', id], ...)`
2. Update **list** caches: `setQueriesData({ queryKey: ['entities'] }, ...)`
3. Invalidate only when deterministic updates are not possible.

Example (update user):

```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";

type User = { id: string; name: string };

export function useUpdateUserMutation() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: async (input: Partial<User> & { id: string }) => {
      return await api.updateUser(input);
    },
    onSuccess: (updated: User) => {
      queryClient.setQueryData(["user", updated.id], updated);

      queryClient.setQueriesData({ queryKey: ["users"] }, (old: unknown) => {
        if (!old) return old;

        if (Array.isArray(old)) {
          return old.map((u) => (u.id === updated.id ? updated : u));
        }

        if (typeof old === "object" && old !== null && "items" in old) {
          const list = old as { items: User[] };
          return {
            ...list,
            items: list.items.map((u) =>
              u.id === updated.id ? updated : u,
            ),
          };
        }

        return old;
      });
    },
  });
}
```

### Invalidation strategy

- Invalidate with the smallest scope: `queryClient.invalidateQueries({ queryKey: ['users'] })`
- Avoid blanket invalidations.
- Prefer targeted `setQueryData` / `setQueriesData` where possible.

## Error/Loading/Empty states (MANDATORY)

Every query-driven UI must handle:

- **Loading:** use `Skeleton` (shadcn/ui) or equivalent
- **Error:** use `Alert` or toast + retry option
- **Empty:** show a clear empty state + next action

- Use discriminated unions for complex UI states.
